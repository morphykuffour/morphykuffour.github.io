{%- comment -%} The carousel behind /art/ and /unc/. It began as the art page's own markup and was lifted here when the second page wanted it: the two differ only in what they are showing, and a hundred lines of scroll logic copied twice is a hundred lines that drift apart at the first fix. Parameters: items list of {file, alt, title, caption, link, width, height}; only `file` is required. `link` makes the picture a link, `caption` writes a line under it, and the pair of dimensions reserves the space so the strip does not reflow as lazy images land. base URL the file names hang off, e.g. "/images/unc/" label aria-label for the strip, e.g. "Saved pins" unit singular noun for the arrows, e.g. "pin" -> "Previous pin" The track is a scroll container with scroll-snap, not a JS slider: with the script off it is still a swipeable, keyboard-scrollable strip of pictures, and with it on the arrows only call scrollTo on that same box. So the carousel has no state of its own to get out of step -- where it is *is* its scroll offset, which is also what a swipe, a trackpad and a focus ring all already move. {%- endcomment -%} {%- assign unit = include.unit | default: 'image' -%}
