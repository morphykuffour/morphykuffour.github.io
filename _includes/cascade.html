It began beside the homepage menu and was lifted here when the elsewhere list wanted one too: the stacks differ only in which file they play, and the phase logic copied out per stack is logic that drifts apart at the first fix. Five call it now -- two floated beside lists a page apart, three laid over the board on the homepage. Parameters: file basename under /videos/, without extension: "crown" plays /videos/crown.mp4 and posters it with /videos/crown-poster.jpg width the file's own pixel dimensions. Both are required -- the stack's height geometry is derived from them (see below), so a wrong pair here is a box of the wrong shape, not merely a hint label what the clip shows, for anyone who cannot see it The stack's geometry is one number and two that fall out of it. Each layer is 78% of the box wide and the two behind it are offset 11% twice, so 78 + 22 = 100 fills the width exactly. The height then follows without being chosen: a layer is 0.78w wide and 0.78w*r tall for the file's ratio r, and the front one starts 0.22h down, so h = 0.78w*r + 0.22h, which is h = w*r. The box's own aspect ratio is the file's -- so it is handed to the CSS from here, where the dimensions are known, rather than written into a stylesheet that would need a new rule per clip. Stating it at all is what reserves the space before the first frame arrives, so the text beside the stack does not jump when the video loads. {%- endcomment -%}
